Choose a route

Start where uncertainty still exists.

Use Discussions for exploration and evidence exchange. Use Issues when work is bounded. Use pull requests for concrete changes. Security vulnerabilities follow the private security route, not a public thread.

Research / reproduction

Prior art / falsification

Evidence boundary

What makes a useful contribution?

Research

Make it reproducible

Exact source version, environment, workload, method, sample size, exclusions, raw artifacts and limitations.

Architecture

Make the alternative explicit

Describe what existing standards or a simpler mechanism can already solve, plus what gets worse if the proposal ships.

Economics

Count control cost

Verification, policy, state and orchestration are not free. Include latency, tokens, compute and human attention where relevant.

Claims

Keep evidence classes separate

Simulation, deterministic tests, live model runs and independent reproduction are different forms of evidence and stay labelled.

Security issues do not belong in public Discussions. Use the security policy and private vulnerability reporting path exposed by the relevant repository.
